# 部署到 fnOS（实验性）

本功能与「证书签发」「DDNS」分开。面向用户的 fnOS 1.2.0602 环境开发，已完成本地适配器与失败注入测试，**尚未在该版本实机验证**。系统内部证书结构、权限或服务不匹配时拒绝写入。

## 安装与使用

1. 安装更新后的 `reverse-proxy.fpk`。主应用仍使用专用普通用户运行。
2. 从 v1.0.10 起，部署服务随主应用安装和启动，无需额外安装助手。主应用仅在生命周期和受限本机部署进程中使用 root，Web 与代理服务强制降权。
3. 先在 fnOS 手动导入一次正式证书并绑定 HTTPS。在本应用的「部署到 fnOS」中点击「检查部署服务」，选择证书库中的来源证书及对应系统证书，填写验证域名与 fnOS 实际 HTTPS 端口（默认 5667）。
4. 保存绑定后点击「预检部署」。预检不写入；确认弹窗中核对目标、到期时间和端口，再确认部署。预检结果有效期 5 分钟，绑定或证书发生变化时必须重做。
5. 首次部署通过 HTTPS 验证后，可独立开启「证书轮换后自动部署」。后台每分钟检查绑定证书 ID 的指纹变化；仅更新时部署，不重新签发。重绑、外部改动或失败都会暂停自动部署。

部署会短暂重载飞牛网络证书服务和 HTTPS 网关。请避开关键传输任务，并保留局域网备用访问方式。此版本不新增系统证书、不修改服务绑定、不写入系统信任根，也不部署到 WebDAV、FTP 等其他服务。

## 安全边界

- 助手不监听 TCP，只接受主应用专用组可访问的本机套接字。没有任意命令、SQL、文件路径、URL 或远程主机执行接口。
- 助手只使用 Node 内置模块，生命周期检查代码和上级目录的 root 所有权及不可被普通用户写入；不将 Web 应用或第三方云 SDK 提升为 root。
- 只更新 `upload` 来源的已有手动导入证书；保护 fnOS 自带证书。来源必须为正式证书，不接受 ACME 测试环境证书。
- 新证书链必须连到 Node 内置的公共 CA 信任根，部署后的 HTTPS 连接也必须通过信任校验。当前不支持私有 CA、自签名证书或缺少中间证书的链；验证旧证书/恢复状态时采用精确指纹固定，允许替换已过期的旧证书。
- 检查证书与私钥、链签名、有效期、完全一致的 DNS SAN、数据库与索引一致性，以及目标绑定。限制大小、数量与路径，拒绝符号链接、硬链接和不安全权限；返回数据和日志不暴露系统证书文件位置、私钥或原始数据库输出。
- 预检与部署前都通过本机实际 HTTPS 连接校验证书指纹，不通过公网 DNS 连接其他服务器。替换前再次检查完整配置快照；数据库使用完整旧记录比较并交换。
- 写入前持久化受限备份及恢复日志。成功后验证服务状态、HTTPS 指纹、文件、数据库和服务绑定。失败按未被外部修改的前提回退，再验证原 HTTPS 指纹；冲突时保留恢复日志并禁止后续写入，不覆盖外部变更。
- 中断后助手启动时尝试恢复，主应用暂停自动部署并要求重新预检。只保留最近 10 份已完成备份，不删除待恢复日志；卸载/升级保留备份，供管理员恢复。
- 系统证书在证书库中仍是实验性只读来源，与这个独立写入功能互不混用。

## 验证与限制

本地测试使用临时文件、模拟数据库及失败注入，覆盖预检零写入、单目标部署、CAS 冲突、TLS 失败回退、中断恢复、路径与权限防护、凭据与路径不回显、确认令牌及自动部署边界。未连接用户 NAS，也未修改真实系统证书或云 DNS。

系统内部接口并非稳定的公开部署 API。首次实机使用请先完成只读预检；结构不兼容应调整适配器并补测试，不应关闭校验或给主应用全局 sudo/root 权限。

## DDNS 公网 IP 检测

DDNS 页提供独立「检测公网 IPv4 / IPv6」按钮，无需 DNS 凭据。后台通过 [ipify 官方接口](https://www.ipify.org/) 获取 **运行应用的 NAS 的出口地址**；IPv4 与 IPv6 分别使用固定 HTTPS 端点，不允许指定自定义检测 URL。每次手动或定时 DNS 同步重新获取地址，先校验类型再写入所选服务商。只读检测不修改 DNS、同步时间或成功记录；失败时保留并明确标注上次检测值。

公网出口 IP 不等于可入站：CGNAT、路由器端口映射、防火墙、VPN/代理出口仍需按实际网络处理。浏览器设备 IP 与 NAS 出口 IP 无关。本地 `DEMO_MODE=1` 不检测真实 IP、不连接助手或云端，也不生成虚假的成功记录。

## 集成版本 v1.0.10

后台部署使用独立的官方 Node.js v22.23.2 Linux x64 / arm64 运行时，构建时固定 SHA-256 校验并随包包含 LICENSE。不会以 root 执行可由共享 Node.js 应用用户修改的运行时。主服务继续使用 fnOS nodejs_v22，并只携带绑定低端口的能力。

旧版独立助手不再需要。若仍在运行，内置服务拒绝并行部署，应先停止旧助手。已有证书与备份保持不变。
